# 3주차 - 생각정리

> 이 파일은 1~4단계 실측이 쌓인 뒤 마지막에 채운다. 지금은 어떤 질문을 끝까지 가져갈지만 남겨둔다.

## 내가 배운 것 후보

- Memory는 LLM의 기억이 아니라, 이전 메시지를 다음 프롬프트 앞에 다시 붙이는 서버 쪽 조립 과정이다.
- `ChatMemoryRepository`, `ChatMemory`, `MessageChatMemoryAdvisor`는 저장소, 정책, ChatClient 연결이라는 서로 다른 책임을 가진다.
- 세션 ID를 잘못 다루면 기능 버그가 아니라 개인정보 사고가 된다.
- "그거"를 잘 답했다는 것과 Tool 파라미터를 정확히 복원했다는 것은 다르다.

## 아직 의문인 것

- Tool 결과가 Memory에 직접 남지 않는 경우, assistant 자연어 응답에 orderId를 얼마나 명시해야 다음 턴이 안정적인가.
- `MAX_MESSAGES`를 턴 수가 아니라 토큰 예산 기준으로 자르는 방식이 필요한가.
- 요약 Memory를 직접 만든다면 언제 요약하고, 어떤 정보를 보존해야 하는가.

## Round 4로 넘길 생각

Memory는 "그 주문", "아까 말한 것" 같은 세션 맥락을 다룬다. RAG는 "배달 지연 보상 정책", "환불 기준"처럼 대화 안에 없던 지식을 다룬다. Round 4에서는 두 advisor가 같이 붙었을 때 어떤 질문이 Memory로 풀리고, 어떤 질문이 RAG로 넘어가는지 보고 싶다.
