## 관찰할 것

이번 단계에서는 Memory가 프롬프트에 끼어드는 장면을 로그로 잡는다.

- 1턴 프롬프트: 사용자 메시지만 들어간 상태
- 2턴 프롬프트: 1턴 USER + ASSISTANT가 앞에 붙은 상태
- advisor 로그: 입력 토큰 증가
- Tool 로그: 지시 대명사 턴에서 실제 Tool 재호출이 일어났는지

1단계 smoke에서는 2턴이 이전 도착 시간을 이어 말했지만, Tool 재호출 로그는 없었다. 이 차이를 본문에서 계속 분리해서 봐야 한다.

## AI 코드 리뷰에서 볼 결함

외부 AI에게 다음 요청을 던지고, 나온 코드를 이번 구현과 비교한다.

```text
Spring AI 1.0으로 배달 챗봇에 대화 메모리 기능을 붙여줘. 세션별로 대화가 유지되어야 해.
```

검토할 위험은 최소 세 가지다.

- 세션 ID가 고정값이거나 공용으로 쓰이는가.
- Memory 크기 제한 없이 모든 메시지를 저장하는가.
- TTL이나 저장소 선택 기준 없이 InMemory만 쓰는가.
- 민감 정보가 평문으로 오래 남는가.
- 멀티 인스턴스 환경을 고려하지 않는가.
